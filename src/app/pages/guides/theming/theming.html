Theming

Every color in this library comes from a small set of seed colors. Each seed expands into a ramp of eleven steps in OKLCH color space, which keeps perceived contrast even from step to step no matter the hue. Radius, spacing, and type also come from a small set of primitives, so building a new theme means changing a handful of values, not hundreds.

Roles

There are seven color roles: primary, accent, danger, info, warning, success, and neutral. Each role exposes its ramp as Tailwind utilities and CSS custom properties, from 50 (lightest) to 950 (darkest).

@for (role of roles; track role) {
{{ role }}
@for (step of steps; track step) {
}
}

Want to see this update live? Try the theme editor.

Semantic tokens

The seven ramps feed a semantic layer of tokens grouped by purpose: surface, text, icon, link, border, and divider. Components use these semantic tokens, such as bg-surface-white, text-text-subdued, or border-divider, instead of a raw ramp step. Each semantic token is a live var() reference to a ramp step (the one token with transparency uses color-mix() instead). Changing a seed color updates every semantic token derived from it automatically, with no separate remapping step.

Base tokens

Radius, letter spacing, typography, and shadows live in styles.css as plain values, not seeds, since they need no color math. Change --radius-base to rescale every rounded utility at once. Change --letter-spacing-base to adjust tracking across the whole type scale. Edit these directly since there is no generation step for them.

Generating the theme

Inside this repository, seed colors live in scripts/theme.seeds.json, one hex value per role: 

{
  "primary": "#D5006C",
  "accent": "#3B3CF7",
  "danger": "#FF4B4B",
  "info": "#007EFF",
  "warning": "#FFC058",
  "success": "#15CC96",
  "neutral": "#7A828C"
}

After editing the seeds, regenerate the stylesheet:

npm run theme:generate

This rebuilds src/styles/theme-colors.css from the seeds.

Using the CLI

A project that installs components through the CLI runs npx ngmona-ui init once. Init asks for a seed color per role, then writes two files: a theme file with the color ramps, and a tokens file with radius, typography, and shadows. Both are imported into your stylesheet for you.

To change colors later without repeating the whole setup, run the theme command: 

npx ngmona-ui theme --primary "#D5006C" --accent "#3B3CF7"
  • Pass any subset of role flags. Roles left out keep their current seed color.
  • Run the theme command with no flags to get prompted for every role instead.
  • The command rewrites the generated theme file and updates the seeds stored in ngmona.json.

Editing generated CSS by hand

theme-colors.css is generated. To change a whole ramp, edit its seed and regenerate instead of editing the file. Ramp steps such as --color-primary-500 are real literal values, so editing one by hand is safe and only affects that step. Everything else in the file, including the bare --color-primary alias and every semantic token, is a reference to a ramp step, so editing a ramp step cascades to everything derived from it. To change one semantic token only, override that specific property somewhere else, such as theme-dark.css or your own stylesheet, instead of editing the primitive it points at.
